# ГБО-АВТО сервис — сайт (Златоуст)

Многостраничный статический сайт автосервиса по установке и обслуживанию
газобаллонного оборудования. Собирается Eleventy в чистый HTML, который
встаёт на любой хостинг, включая шаред на reg.ru.

Визуальный язык клонирован с rossko.ru — шапка-плашка, разделитель
«плашка + волосяная линия», полоса цифр, плиточная сетка, крупные карточки
с обрезанным изображением. Структура и содержание свои: это автосервис,
а не каталог запчастей, поэтому ни поиска, ни корзины на сайте нет.

- Рантайм-зависимостей нет. CSS рукописный, JS ванильный, без CDN в проде.
- Шрифт один — Golos Text 400/500/600/700, самохостом, сабсет: 44 КБ на всё.
- Иконки — один набор Phosphor, спрайтом, одинаковая толщина штриха.
- Все тексты, цены, услуги, отзывы, контакты — в `src/_data/*.json`.

## Запуск

```bash
npm install
npm run images     # готовит .webp и фолбэки из PNG (нужен pillow)
npm start          # http://localhost:8080 с автоперезагрузкой
npm run build      # прод-сборка в dist/
npm run preview    # однофайловое превью всего сайта -> preview/site-preview.html
```

`npm run preview` складывает все десять страниц, стили, скрипты и шрифты
в один HTML без единого внешнего запроса — файл можно отправить заказчику
ссылкой или открыть с телефона, калькулятор и квиз в нём работают.

Публикация: содержимое `dist/` кладётся в корень сайта на хостинге.

## Изображения

| Файл | Где |
|---|---|
| `gbo-kit-hero` | Первый экран главной и `/ustanovka-gbo/`, правая колонка. Вписан по высоте: 560px на десктопе, 320px на мобиле |
| `gbo-kit-diagonal` | Тёмная карточка на главной и CTA-блок внутренних страниц. Крупнее контейнера и обрезается правым и нижним краем — это приём, вписывать целиком нельзя. На мобиле скрыт |
| `equip-reducer`, `equip-injectors`, `equip-ecu`, `equip-tank-toroidal` | Плитки оборудования на главной и в блоке «Что входит в комплект» на `/ustanovka-gbo/` |
| `avatar-512` | Блок «Мастер подберёт комплект» на главной и `/kontakty/` |
| `avatar-circle-112` | Чат-виджет, 56×56 CSS-пикселей |

Положите PNG в `assets/img/` и выполните `npm run images` — скрипт сделает
`.webp`, растровый фолбэк и запишет размеры в `manifest.json`, чтобы шаблон
проставил явные `width`/`height`.

Скрипт **не перезаписывает уже готовые файлы**: пережимать сжатое — терять
качество. Полная пересборка — `python3 tools/build-images.py --force`.
Исходником может быть и сам `.webp` (когда PNG в репозиторий не кладём):
тогда скрипт только дописывает растровый фолбэк и помечает запись
`"src": "webp"`, чтобы на следующем прогоне не принять этот фолбэк
за исходник.

**Пока файла нет, на его месте выводится плашка с именем файла.** Вёрстка
при этом целая, страницы открываются, подстановка ассета правок в шаблонах
не требует. Слоты, помеченные `optional: true`, вместо плашки не выводят
ничего.

### Два приёма, которые стоит знать при замене файлов

Предметная съёмка снята на белом фоне, а плитка залита `--mist`. Белый
квадрат на сером читался бы заплаткой, поэтому кадры на сборке умножены
на цвет плитки: фон изображения совпадает с фоном плитки пиксель в пиксель,
рамка и своя тень не нужны. При смене цвета `--mist` кадры надо пересобрать.

`gbo-kit-diagonal` лежит на тёмно-зелёной карточке, поэтому у него снят фон
(альфа-канал) и `tools/deshadow.py` дополнительно убрал мягкую контактную
тень: на белом она читается естественно, а на тёмном превращается в светлое
пятно вокруг деталей.

`gbo-kit-hero` лежит на белой странице, и тень у него уходит вправо-вниз, где
её обрезает рамка кадра. Ровный серый обрыв на белом читается не как тень, а
как подложка под картинкой, поэтому `tools/fade-edges.py` растворяет тень к
правому и нижнему краю. Осветляется только фон — светлый, нейтральный по цвету
и гладкий, связанный с рамкой заливкой; предмет эти признаки не проходит.
Оба скрипта переписывают `.webp` на месте, так что после них нужен
`npm run images` (фолбэк пересобирается только если его удалить).

### Отзывы — правило без исключений

В `reviews.json` попадают **только реальные отзывы с карточки 2ГИС,
дословно**. Придумывать отзывы, добавлять имена или править формулировки
нельзя: карточка 2ГИС публична, расхождение видно любому посетителю за
десять секунд, а отвечает за недостоверную рекламу владелец сервиса.
Если отзывов мало — лента добирается слайдами другого типа из массива
`extra` (гарантия, документы, рейтинг), но не выдуманными цитатами.

## ⚠️ `reviewGating` — прочитайте до включения

В `src/_data/site.json`:

```json
{ "reviewGating": false }
```

**`false` — значение по умолчанию, безопасное.** После любой оценки
посетитель видит благодарность и ссылку на 2ГИС. При оценке 1–3
дополнительно раскрывается поле «Что пошло не так?», текст уходит
владельцу в Telegram. Ссылка на 2ГИС остаётся доступна всем.

**`true` включает review gating:** оценки 4–5 ведут сразу на 2ГИС,
а 1–3 уводятся только во внутреннюю форму.

Схема, при которой ссылка на площадку показывается только довольным
клиентам, называется review gating, и правила площадок отзывов её прямо
запрещают. При обнаружении карточка компании может получить
предупреждающую пометку или лишиться части отзывов. **Риск несёт владелец
сервиса, а не разработчик сайта.** Включайте флаг только осознанно.

## Чат-виджет

Свёрнутое состояние — кружок с аватаркой мастера, зелёная точка «онлайн»,
счётчик непрочитанного и реплика-затравка. Появляется через 18 секунд или
на 40 % прокрутки, что раньше; на мобиле реплика скрыта, только кружок.

Развёрнутое — переписка, а не анкета: мастер «печатает», реплики приходят
по одной, ответы клиента встают справа зелёными пузырями, у сообщений
время. Варианты ответа — чипы под лентой, свободный ввод и телефон —
поле со стрелкой отправки.

Крестик в шапке чата **сворачивает** в кружок и сохраняет переписку.
Скрыть виджет до конца сессии можно только крестиком на самом кружке —
это запоминается в `sessionStorage`.

Сценарий жёстко заскриптован в `assets/js/app.js`. Ни языковой модели,
ни внешних API: виджет отвечает клиентам сервиса про цены и сроки, и
однажды ответил бы неправильно — разгребать пришлось бы владельцу.

## Заявки

Три источника — форма заявки, чат-виджет, форма фидбэка из блока оценки —
шлют POST на один адрес из `site.json` → `relayUrl`. Слой отправки вынесен
в `window.gboSend`, поэтому смена адреса приёмника не требует правок
в компонентах.

Заявки уходят владельцу в Telegram **на номер +7 951 469-33-35**. Сам номер
сайту не нужен и в клиентский код не попадает: пересылкой занимается
Worker (`worker/index.js`), а chat_id этого аккаунта задаётся у него
в переменной окружения `TELEGRAM_CHAT_ID`. Для справки номер записан
в `site.json` → `telegramNotifyPhone`.

**Токен бота в клиентском коде отсутствует и появиться в нём не должен.**
Токен живёт только в переменной окружения Worker `TELEGRAM_TOKEN`.
Как получить chat_id и развернуть релей — в `worker/README.md`.

Пока `relayUrl` пуст, формы честно показывают ошибку и телефон запасным
каналом — молча делать вид, что заявка ушла, нельзя.

Защита: honeypot-поле и минимальная задержка 3 секунды от загрузки
страницы до отправки (`formMinSeconds` в `site.json`).

## Перед публикацией

1. В `site.json` заменить `url` на боевой домен.
2. Развернуть релей из `worker/`, задать `TELEGRAM_TOKEN`, `TELEGRAM_CHAT_ID`
   и `ALLOWED_ORIGIN`, затем указать адрес Worker в `site.json` → `relayUrl`.
3. Указать `metrikaId`, если нужна Яндекс.Метрика. Цели уже расставлены:
   `form_submit`, `quiz_complete`, `calc_used`, `phone_click`,
   `whatsapp_click`, `rating_given`, `gis_click`.
4. Изображения уже в репозитории. Если заменяете — положить файлы
   в `assets/img/` и выполнить `npm run images`.
