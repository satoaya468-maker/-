# Строй Сам — B2B-портал заказа стройматериалов

Портал заказа стройматериалов с базы на Западном шоссе в Магнитогорске.
Next.js 15 (App Router), TypeScript, Tailwind CSS.

Задача интерфейса одна: прораб или снабженец должен оформить заказ
за минуту, стоя на объекте, с телефона, в перчатках. Всё остальное
подчинено этому.

```bash
npm install
cp .env.example .env.local   # все ключи необязательны, см. ниже
npm run dev                  # http://localhost:3000
```

## Дизайн-решение

**Сцена, из которой всё выведено.** Прораб в 6:40 утра на бетонной
площадке, минус восемнадцать, снежный отсвет бьёт в экран телефона; ему
нужно заказать 20 тонн щебня до начала смены.

Отсюда следует всё остальное:

* **Рабочая поверхность светлая**, а не тёмная — на солнце и снегу тёмная
  тема нечитаема. Тёмный графит остаётся хромом: шапка, герой, калькулятор,
  подвал. Это же даёт послойную глубину (четыре ступени `--e1`…`--e4`).
* **Один несущий акцент — сигнальный жёлтый hi-vis** на графите. Это
  палитра, которую аудитория носит на себе: жилет, дорожный знак, ковш
  экскаватора. Заодно она обходит рефлекс категории — зелёный «Лемана»
  и оранжевый «Добрострой».
* **Крупные цели нажатия**: основные кнопки 48–52 px, шаговые кнопки
  количества 44 px. Меньше — не попасть в рабочей перчатке.
* **Табличные цифры** (`.tnum`) во всех ценах и тоннаже: при пересчёте
  сумма не должна «прыгать».
* **Шрифты подобраны по контрастной оси**: Oswald (узкий signage-гротеск,
  каким подписывают склады) для дисплейных заголовков и Golos Text
  (кириллический UI-шрифт) для интерфейса. Оба с полной кириллицей.

### Токены цвета

Цвета хранятся **компонентами OKLCH** (`--hv-c: 0.858 0.172 92`), а не
готовыми `oklch(...)`. Из компонентов собирается и сплошной цвет
(`--hv`), и любая прозрачность через Tailwind (`bg-graphite-950/95`).

Это не стилистика, а необходимость: Tailwind молча выбрасывает модификатор
прозрачности для цвета, записанного как готовая функция, и элемент
остаётся вообще без фона. Именно так шапка однажды стала прозрачной,
а подложка модалки — невидимой.

Значения прозрачности берутся из стандартной шкалы Tailwind
(`/10`, `/15`, `/20`…): `/12` не существует и тоже не сгенерируется.

## Единицы измерения

Прораб мыслит кубами, база отгружает тоннами. Всё расхождение между этими
мирами живёт в одном файле — `lib/units.ts`.

У каждого товара есть базовая единица и список доступных; `factor` —
сколько базовых единиц в одной такой. Для сыпучки `factor` куба равен
насыпной плотности материала, поэтому пересчёт «тонны ↔ кубы» получается
сам собой.

При переключении единицы **сохраняется физический объём**, а не число
в поле: 5 т щебня остаются 3,6 м³, а не превращаются в 5 м³.

Калькулятор закладывает запас на уплотнение (+20 % щебень, +15 % песок) —
без него на объект приезжает недосып.

## Интеграции

Все три интеграции включаются переменными окружения и **до включения
работают на локальных данных**: витрина, расчёт и приём заявок
функционируют без единого ключа.

| Переменная | Что включает | Поведение без неё |
|---|---|---|
| `ANTHROPIC_API_KEY` | ИИ-менеджер через Claude API | Правиловый резерв: считает объём по тем же формулам и собирает телефон |
| `MOYSKLAD_TOKEN`, `MOYSKLAD_STORE_ID` | Остатки, цены, резерв под заказ | Локальный каталог, синтетический номер заказа |
| `YOOKASSA_SHOP_ID`, `YOOKASSA_SECRET_KEY` | Онлайн-оплата картой | Заказ оформляется, оплату согласует менеджер |
| `CRM_WEBHOOK_URL` | Отправка лидов в Битрикс24 / amoCRM | Лид пишется в лог сервера — заявка не теряется |
| `NEXT_PUBLIC_SITE_URL` | `return_url` оплаты, canonical | Значение по умолчанию |

Юрлицам счёт выставляется всегда, минуя эквайринг: ООО не платит картой
на 400 тысяч. Развилка «физлицо / юрлицо» — в `lib/payments/yookassa.ts`.

## Сбор лидов

Телефон — единственное обязательное поле во всех формах. Точек входа
пять: герой, калькулятор, карточка товара (заказ в 1 клик), корзина
и чат. Все ведут в `lib/leads.ts`.

Ошибка CRM не отменяет заявку: лид пишется в лог и пользователю всё равно
подтверждается приём. В чате номер перехватывается **до** вызова модели —
ответ может не дойти, лид должен.

## Изображения

Фотостоки недоступны из среды сборки, поэтому материалы нарисованы
вектором (`components/art/`): щебень — угловатыми гранями, песок — зерном
через `feTurbulence`, цемент — штабелем мешков на поддоне. Раскладка
зёрен детерминирована (seeded PRNG), иначе сервер и клиент нарисуют
разные картинки и React сорвёт гидратацию.

Чтобы заменить на фотографии: подставьте `next/image` вместо `MaterialArt`
в `ProductCard`, `QuickCategories` и `HeroBackdrop` — форма пропсов
(`kind`, `seed`) для этого и нужна.

## Доступность и адаптивность

* Проверено на 320, 360, 390, 414, 768, 1024, 1280, 1440 и 1920 px —
  горизонтальной прокрутки нет ни на одной ширине.
* Контрасты проверены инструментально: нарушений AA на главной нет.
* Модалка — нативный `<dialog>`: фокус-ловушка, Esc и верхний слой
  достаются от платформы и не обрезаются `overflow: hidden` родителя.
* Все поля имеют видимые `<label>`; ошибки показываются после ухода
  из поля, а не на втором введённом символе.
* `prefers-reduced-motion` останавливает ленту офферов, оставляя её
  читаемой, и отключает входные анимации.
* Бегущую строку можно остановить кнопкой, наведением и фокусом.
